# Implementation Plan: writer-workspace

## Overview

This plan implements the `writer-workspace` feature in dependency order across
the three mandated layers: Business Logic (`Extraction_Helper`), Backend
persistence + `Writer_API`, and Frontend `Writer_UI`. Each layer builds on the
previous one and ends by wiring the pieces together, so there is no orphaned
code. It depends on the `accounts` spec for the `current_user` dependency and the
`users` table, and it **produces** the persisted Writer uploads that
`reproducibility-scoring` and `code-generation` (case 3) consume.

- **Backend verification gate:** after every backend task, `cd backend && uv run pytest`
  must pass (pytest + testcontainers against a throwaway `postgres:17`, run on
  the host per `backend/README.md`).
- **Schema:** the `paper_claims`, `writer_manuscripts`, and `writer_source_files`
  tables are created by an Alembic migration committed under
  `backend/alembic/versions/` and applied via `alembic upgrade head` (the
  container entrypoint) — **never** `create_all`. Verify the autogenerated draft
  emits the `ON DELETE CASCADE` child FKs and the composite unique index on
  `(claim_id, path)`; add them by hand if autogenerate omits them.
- **Persisted content is the ADR-0003 carve-out:** store only derived manuscript
  text and unpacked `(path, content)` source files; discard raw PDF bytes
  (R6.7) and the raw archive / fetched repo working copy (R7.8). Store no
  Reader-side indexed-Paper full text or external repository contents (R9.7).
- **No code execution:** the `Extraction_Helper` never executes, builds, or runs
  any uploaded or unpacked content (R10.8).
- **New dependencies:** backend deps via `uv` (a pure-Python PDF text library
  such as `pypdf`, and `hypothesis` in the dev group); archive handling uses the
  stdlib (`zipfile`/`tarfile`) and the codeload tarball fetch uses `httpx`
  (already bundled by `fastapi[standard]`, so no new dep and **no `git` binary**).
  Frontend deps (if any) via `pnpm`.
- **Frontend verification:** there is **no automated frontend test gate** — the
  team tests the UI manually. Frontend tasks are verified manually; do not invent
  a frontend test suite.
- Property-based tests use **Hypothesis** (min. 100 iterations each) and are
  tagged with a comment referencing the design property they validate.

  - [x] 1.3 Implement the `Extraction_Helper`
    - Create `backend/app/core/extraction.py` with no FastAPI/SQLModel imports.
    - Define `SourceFile(path, content)`, `ExtractionError`, `UnpackError`,
      `LimitExceeded`.
    - `extract_pdf_text(data) -> str`: return the extracted non-empty text; raise
      `ExtractionError` for a non-readable PDF or when the extracted text is empty
      (e.g. a pure scan with no text layer).
    - `unpack_archive(data) -> list[SourceFile]`: detect zip or tar(.gz/.bz2/.xz);
      return one `SourceFile` per **regular, text-decodable** file; reject
      path-escaping entries (absolute / `..`); skip directories, symlinks, device
      entries, and **binary files** (UTF-8 decode failure or a null-byte sniff);
      enforce `max_source_files` and `max_source_total_bytes` **while reading**
      (raise `LimitExceeded`, never a partial set); raise `UnpackError` on an
      unsupported/corrupt archive. A Git URL is handled by downloading the host's
      codeload tarball and passing its bytes to this same function — there is no
      separate tree-unpack path.
    - Never execute, build, or run any content.
    - _Requirements: 10.1, 10.2, 10.3, 10.4, 10.5, 10.6, 10.7, 10.8_

  - [x] 1.4 Add Hypothesis to the dev dependency group

  - [ ] 5.2 Implement the manuscript upload and delete endpoints
    - `POST /api/writer/claims/{id}/manuscript` (multipart PDF, owner-scoped):
      enforce `max_manuscript_bytes` (`413`); call `extract_pdf_text`; on
      `ExtractionError` return `422` with the reason leaving any existing
      manuscript unchanged; on success upsert the single `WriterManuscript`
      (replace), discard the raw bytes, return `200 ManuscriptRead`.
    - `DELETE /api/writer/claims/{id}/manuscript` → `204`, removing only the
      manuscript (claim + source intact); `404`/`401` owner-scoped.
    - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 6.7, 8.3_

  - [ ] 5.3 Implement the source upload and delete endpoints
    - `POST /api/writer/claims/{id}/source` (multipart archive **or**
      `{git_url}`, owner-scoped): for an archive enforce
      `max_source_archive_bytes` and call `unpack_archive`; for a `git_url`
      parse it into `(host, owner, repo, ref?)` — honoring a `/tree/<ref>` or
      tag ref in the URL, else the default branch — resolve it to the host's
      codeload archive endpoint and HTTP-download the tarball under
      `git_fetch_timeout_seconds` (no `git` clone; reject an unsupported host, an
      unreachable URL, or a 4xx/auth response with `422`), then pass the tarball
      bytes to `unpack_archive`. On `UnpackError`/fetch failure return `422` and
      on `LimitExceeded` return `413`, leaving any existing source unchanged. On
      success replace the whole `WriterSourceFile` set (delete-old-then-insert-new
      in one transaction), discard the archive / tarball bytes, return
      `200 SourceRead` with the stored `paths` and the `skipped_paths` dropped as
      binary.
    - `DELETE /api/writer/claims/{id}/source` → `204`, removing only the source
      set (claim + manuscript intact); `404`/`401` owner-scoped.

## Notes

- Tasks marked with `*` are optional and can be skipped for a faster MVP; they
  are all tests. The core Writer flow (unmarked tasks) is required.
- This spec **produces** the persisted Writer uploads that `code-generation`
  (case 3) and `reproducibility-scoring` consume; it neither generates code nor
  computes any score.
- Each task references specific requirements and/or design Property numbers for
  traceability.
- Backend gate: `cd backend && uv run pytest` (pytest + testcontainers, run on
  the host). Property tests use Hypothesis at ≥100 iterations.
- Schema is created by a committed Alembic migration under
  `backend/alembic/versions/` and applied via `alembic upgrade head` — never
  `create_all`. Confirm the `ON DELETE CASCADE` child FKs and the `(claim_id,
  path)` composite unique are present (add by hand if autogenerate omits them).
- Persisted content is the ADR-0003 carve-out: derived manuscript text + unpacked
  `(path, content)` source only; raw PDF bytes and the raw archive / repo working
  copy are discarded after ingestion. No code is ever executed.
- Frontend has no automated test gate; verify UI manually.
- A public Git URL is fetched as an HTTP codeload tarball (not cloned,
  `docs/adr/0006`) and run through `unpack_archive`; tested with a mocked HTTP
  transport returning a canned tarball — never a live remote.
- Source storage is text-only: binary files in an upload are skipped
  (`docs/adr/0003` boundary, refined during grilling).
